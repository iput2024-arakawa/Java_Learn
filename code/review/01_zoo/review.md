# 復習1（動物園）レビュー

## 1. 動作確認

コンパイル・実行ともに成功しています。要件（抽象クラス、継承、ポリモーフィズム、インターフェース）の
構造自体は正しく実装できていますが、**出力内容が期待出力と一部ズレています**。

実際の出力：
```
ポチ(犬種 : 柴犬ワンワン！
ピーちゃん: チュンチュン！
ポチにドックフードをあげた
ピーちゃんに木の実をあげた
型番AIBO-X1に電池を補給した
```

期待される出力（`problem.md`より）：
```
ポチ（犬種：柴犬）: ワンワン！
ピーちゃん: チュンチュン！
ポチにドッグフードをあげた
ピーちゃんに木の実をあげた
```

差分は2点、`Dog.java`にあります。

### 差分1：`makeSound()`の出力（Dog.java 14行目）

```java
System.out.println(getName() + "(犬種 : " + breed + "ワンワン！");
```

- 閉じ括弧`）`が抜けている（`"柴犬"`の後に`）`がない）
- 半角の`(`・`:`を使っているが、期待出力は全角の`（`・`：`
- `breed`の直後に`）: `を挟まず、そのまま`"ワンワン！"`を続けてしまっている

### 差分2：`feed()`の出力（Dog.java 19行目）

```java
System.out.println(getName() + "にドックフードをあげた");
```

「ドック**フ**ード」ではなく「ドッ**グ**フード」が正しい表記です（濁点の抜け）。

## 2. Javaらしい書き方

### 改善点：`main.java`のクラス名

```java
public class main{
```

Javaでは**クラス名は先頭大文字のPascalCase**（`Main`、`Dog`、`RobotPet`のように）にするのが規約です。
現状`main`（小文字）になっているので`Main`に直しましょう。

Pythonではモジュール名・関数名は`snake_case`が主流ですが、Javaではクラス名だけ特別に
`PascalCase`というルールがあります。これは「クラスは型（設計図）であり、変数やメソッドとは
違う種類のものだ」という区別をコンパイラではなく**人間が読んだときに一目でわかるようにするため**の
慣習です（コンパイラ的には小文字でもエラーにはなりません。今回実際に`main.java`のまま
コンパイル・実行が通ったのがその証拠です）。

### 参考情報：`Bird.java`のコンストラクタの順序について

```java
public Bird(String name, int age, boolean canFly){
    this.canFly = canFly;
    super(name, age);   // ← superより前に文がある
}
```

実は通常のJavaのルールでは、**`super(...)`（親のコンストラクタ呼び出し）はコンストラクタ内で
必ず最初の文でなければならない**、という制約があります。これは「親クラス部分がまだ初期化されて
いない状態で、子クラスのフィールドに値を入れてしまうと、中途半端な状態のオブジェクトができて
しまう」ことを防ぐための安全装置です。

本来ならこのコードは以下のようなコンパイルエラーになるはずです。

```
error: call to super must be first statement in constructor
```

ですが、今回この環境で使っているJavaのバージョン（JDK 26）では、**「Flexible Constructor Bodies」
という比較的新しい機能**が導入されていて、「親クラスのフィールドに一切触れない文であれば、
`super(...)`より前に書いてもよい」というルールに緩和されています。今回の
`this.canFly = canFly;`は`Bird`自身のフィールドへの代入で、親（`Animal`）のフィールドには
触れていないため、このルールの範囲内でコンパイルが通ってしまいました。

とはいえ、これはかなり新しい・発展的な機能で、多くの教材や少し前のJavaバージョンではまだ
使えません。初学者のうちは**「`super(...)`は必ず一番最初に書く」という従来のスタイルに
統一しておく**ことを強くおすすめします（`Dog.java`の方は正しくこの順序で書けています）。

### 良い点

- `name`・`age`・`breed`・`canFly`・`model`をすべて`private`にでき、カプセル化ができている
- `Dog`・`Bird`ともに`super(...)`で親のコンストラクタを正しく呼べている（順序以外）
- `makeSound()`・`feed()`に`@Override`を正しく付与できている
- `Animal[]`配列と`Feedable[]`配列を使い分け、継承によるポリモーフィズムと、
  継承関係のないクラス同士をインターフェースでまとめる、という2つの異なる仕組みを
  両方正しく実演できている
- `RobotPet`が`Animal`を継承せず`Feedable`だけを`implements`する、という要件通りの
  設計になっている（`getName()`などAnimal側のメソッドに依存していない）

## 3. 模範解答例

### Dog.java（修正版・抜粋）

```java
@Override
public void makeSound(){
    System.out.println(getName() + "（犬種：" + breed + "）: ワンワン！");
}

@Override
public void feed(){
    System.out.println(getName() + "にドッグフードをあげた");
}
```

`getName()`の直後に`（犬種：`、`breed`の直後に`）: `を挟むことで、全体として
`"ポチ（犬種：柴犬）: ワンワン！"`という1つの文字列になります。文字列連結（`+`）は
書いた順番通りにそのまま繋がるだけなので、期待する出力を先に書き出してから、
どこが変数（`getName()`や`breed`）でどこが固定文字列かを分解すると間違えにくいです。

### Bird.java（修正版・抜粋）

```java
public Bird(String name, int age, boolean canFly){
    super(name, age);
    this.canFly = canFly;
}
```

`super(...)`を最初の行に戻しています。

### Main.java（クラス名修正）

```java
public class Main{
    public static void main (String[] args){
        // 中身はそのままでOK
    }
}
```

ファイル名も`main.java`から`Main.java`にリネームしてください（`public class`の名前と
ファイル名は一致させる必要があります）。
