# 競技プログラミング演習（OOP学習と並行するトラック）について

## この演習の目的

オブジェクト指向の学習（`notes/`・`code/`）とは別に、**「与えられた問題を効率よく
解くための思考力」＝アルゴリズム的思考**を鍛えるための、並行トラックです。
AtCoder（競技プログラミングの代表的なサイト）のような問題形式に慣れることを目標にします。

## 進め方

- `competitive/`フォルダの中に、問題ごとにサブフォルダを作ります（`competitive/001_xxx/`
  のように3桁の連番＋内容）
- 各フォルダの`problem.md`に、問題文・制約・入出力例を書きます
- 提出コードは同じフォルダに`Main.java`として作成してください
- 最初の3問（001〜003）は**今の実力を測る診断**として、やさしい問題からやや考えさせる
  問題まで用意しました。この結果を見ながら、今後の難易度を調整していきます

OOP側のような「座学→演習」の順序は必須ではありません。分からない構文が出てきたら、
その都度このファイルや問題文中のヒントで補足します。

## Javaで標準入力を受け取る方法（Scanner）

競プロでは、入力はキーボードから対話的に打つのではなく、**標準入力**としてまとめて
与えられます（Pythonの`input()`に相当します）。

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int a = sc.nextInt();  // 空白・改行区切りで次のint値を読む
        int b = sc.nextInt();
        System.out.println(a + b);
    }
}
```

Pythonとの対比：

```python
a, b = map(int, input().split())
print(a + b)
```

Javaの`Scanner`は、空白や改行をまたいで「次のトークン」を自動的に読み取ってくれるため、
1行に複数の値が並んでいても、複数行に分かれていても、`nextInt()`などを必要な回数
呼べば読み取れます。

よく使うメソッド：

- `sc.nextInt()`：次の整数を読む
- `sc.next()`：次の単語（空白区切り）を文字列として読む
- `sc.nextLine()`：次の1行をまるごと文字列として読む（`nextInt()`の直後に呼ぶと、
  改行だけを読んでしまい空文字になる、という有名な落とし穴があります。困ったら聞いてください）

## 評価の観点

OOPの演習とは少し違い、競プロ的な問題では以下も見ます。

1. 正しく動くか（要件を満たすか）
2. 想定される最大の入力サイズでも十分な速さで動くか（**計算量**の考え方）
3. 読みやすいコードか

2番目の「計算量」（処理にかかる時間がデータ量に対してどう増えるか、という考え方。
`O(N)`や`O(N^2)`のような表記を使います）は今回が初出の考え方なので、
最初の数問を通して少しずつ説明していきます。
