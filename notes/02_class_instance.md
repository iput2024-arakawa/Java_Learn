# トピック2: クラスとインスタンス（フィールド・メソッド・コンストラクタ）

## 1. これは何か、なぜ必要か

「クラス」とは、データ（属性）とそれに関する処理（振る舞い）をひとまとめにした
**設計図**です。「インスタンス」とは、その設計図から実際に作られた**実体（もの）**です。

例えば「犬」というクラスがあれば、「名前」「年齢」といったデータ（フィールド）と
「鳴く」「走る」といった処理（メソッド）を1つにまとめられます。
そして「ポチ」「タロウ」といった個々の犬がインスタンスです。

なぜ必要かというと、関連するデータと処理をバラバラの変数・関数として管理すると、
プログラムが大きくなったときに「このデータはどの処理と関係あるのか」が分からなくなり、
管理が破綻するからです。クラスはこれを1つの単位にまとめ、
「現実の物事」に近い形でモデル化できるようにします。

これまでの`Main`クラスは「プログラムの入口」として1つだけ使ってきましたが、
これからは目的に応じて複数のクラスを作り、それらを組み合わせてプログラムを作ります。

## 2. Javaでの書き方・構文（最小サンプル）

```java
// Dog.java（別ファイルとして作るのが基本だが、ここでは説明のため1ファイルにまとめる）
public class Dog {
    // フィールド（インスタンスが持つデータ）
    String name;
    int age;

    // コンストラクタ（インスタンス生成時に呼ばれる特別なメソッド）
    public Dog(String name, int age) {
        this.name = name; // this.name = 「このインスタンスのnameフィールド」
        this.age = age;    // 引数のnameと区別するためthisを使う
    }

    // メソッド（インスタンスが持つ振る舞い）
    public void bark() {
        System.out.println(name + "が鳴きました：ワン！");
    }
}
```

```java
public class Main {
    public static void main(String[] args) {
        // クラス（設計図）からインスタンス（実体）を作る = new
        Dog dog1 = new Dog("ポチ", 3);
        Dog dog2 = new Dog("タロウ", 5);

        dog1.bark(); // ポチが鳴きました：ワン！
        dog2.bark(); // タロウが鳴きました：ワン！

        System.out.println(dog1.name + "は" + dog1.age + "歳");
    }
}
```

ポイント：
- `new クラス名(引数...)` … インスタンスを生成する構文。Pythonの`Dog(...)`だけで済むのと違い、
  Javaでは必ず`new`が必要
- `フィールド` … クラスの中に書く変数。インスタンスごとに別々の値を持てる
- `コンストラクタ` … クラス名と同じ名前で戻り値の型を書かない特殊なメソッド。
  インスタンス生成時（`new`した瞬間）に自動的に呼ばれ、フィールドの初期値を設定するのに使う
- `this` … 「このインスタンス自身」を指すキーワード。コンストラクタの引数名とフィールド名が
  同じ場合に、両者を区別するために使う
- `インスタンス変数.フィールド名` / `インスタンス変数.メソッド名()` … `.`（ドット）で
  インスタンスの中身にアクセスする

## 3. Pythonとの対比

Pythonでもクラスは使いますが、書き方がかなり異なります。

```python
# Python
class Dog:
    def __init__(self, name, age):  # コンストラクタに相当
        self.name = name
        self.age = age

    def bark(self):
        print(f"{self.name}が鳴きました：ワン！")

dog1 = Dog("ポチ", 3)  # newは不要
dog1.bark()
```

```java
// Java
public class Dog {
    String name;
    int age;

    public Dog(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void bark() {
        System.out.println(name + "が鳴きました：ワン！");
    }
}

Dog dog1 = new Dog("ポチ", 3); // newが必須
dog1.bark();
```

| 項目 | Python | Java |
|---|---|---|
| コンストラクタ | `__init__(self, ...)` という決まった名前 | クラス名と同じ名前のメソッド |
| インスタンス生成 | `Dog("ポチ", 3)`（`new`不要） | `new Dog("ポチ", 3)`（`new`必須） |
| 自分自身を指す | `self`（引数として明示的に書く） | `this`（暗黙的に使える） |
| フィールドの型 | 書かなくてよい（動的型付け） | `String name;` のように型を明示 |
| メソッドの戻り値の型 | 書かなくてよい | 必ず書く（何も返さない場合は`void`） |

なぜJavaではこのようにするのかというと、Javaは「コンパイル時にすべての型と構造を
確定させる」言語だからです。フィールドの型、メソッドの引数・戻り値の型を
すべて事前に宣言することで、コンパイラが「間違った型のデータを渡していないか」を
実行前にチェックできます。Pythonは実行時まで柔軟に型が決まらない分、
自由度は高いですが、こうした事前チェックはできません。

## 4. つまずきやすいポイント・よくある間違い

- **`new`の付け忘れ**：Pythonの感覚で`Dog dog1 = Dog("ポチ", 3);`と書くとコンパイルエラー。
  Javaでは必ず`new`が必要
- **コンストラクタに戻り値の型を書いてしまう**：`public void Dog(...)`のように書くと、
  それは「コンストラクタ」ではなく「Dogという名前の普通のメソッド」になってしまう
  （戻り値の型は一切書かない）
- **`this`を忘れる**：コンストラクタの引数名とフィールド名が同じとき、
  `this.name = name;`の`this.`を忘れると、フィールドに値が代入されず
  「意味のない自己代入」になってしまう
- **ファイルとクラスの対応**：`public`が付いたクラスは、ファイル名とクラス名を
  一致させる必要がある（`Dog`クラスなら`Dog.java`というファイル名）。
  ただし演習では最初、1つの`.java`ファイルに複数クラスを書いても動作確認自体はできる
- **フィールドとローカル変数の混同**：クラスの中（メソッドの外）に書く変数が「フィールド」、
  メソッドの中だけで使う変数が「ローカル変数」。似ているが役割が違う
