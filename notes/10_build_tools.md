# トピック10: ビルドツール（Maven / Gradle）とプロジェクト構成

## 1. これは何か、なぜ必要か

これまでは`javac Main.java`のように、ファイルを1つずつ手でコンパイルしてきました。
しかし実務のJavaプロジェクトでは、次のような問題が出てきます。

- 他の人が作った便利なライブラリ（外部の`.jar`ファイル）を使いたいが、どこから
  ダウンロードして、どうクラスパスに通すのかを手動で管理するのは大変
- ファイルが数百〜数千個になったとき、手動コンパイルは非現実的
- 「テストだけ実行する」「本番用にパッケージ化する」といった作業を毎回同じ手順で行いたい

**ビルドツール**は、これらを「設定ファイル1つ」で自動化してくれる仕組みです。
Javaの世界では**Maven**と**Gradle**が二大巨頭で、どちらも「依存ライブラリの管理」
「コンパイル」「テスト実行」「パッケージ化」を担います。

## 2. Javaでの書き方・構文（最小サンプル）

### Maven（`pom.xml`）

```xml
<project>
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.example</groupId>
  <artifactId>my-app</artifactId>
  <version>1.0</version>

  <dependencies>
    <!-- 使いたい外部ライブラリをここに書くだけで、自動的にダウンロードしてくれる -->
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.10.0</version>
      <scope>test</scope>
    </dependency>
  </dependencies>
</project>
```

```bash
mvn compile   # コンパイル
mvn test      # テスト実行
mvn package   # jarファイルとしてパッケージ化
```

### 標準的なディレクトリ構成

```
my-app/
├── pom.xml
└── src/
    ├── main/
    │   └── java/       ← 実際のプログラムコード
    └── test/
        └── java/       ← テストコード
```

MavenでもGradleでも、この`src/main/java`という構成はほぼ共通の慣習です。
プロジェクトを開いたとき、この形になっていればビルドツールが自動的に認識してくれます。

## 3. Pythonとの対比

| 役割 | Python | Java |
|---|---|---|
| 依存ライブラリの宣言 | `requirements.txt`（または`pyproject.toml`） | `pom.xml`（Maven）／`build.gradle`（Gradle） |
| 依存ライブラリのインストール | `pip install -r requirements.txt` | `mvn install`（自動ダウンロード） |
| 仮想環境 | `venv`でプロジェクトごとに環境を分離 | プロジェクトごとに`pom.xml`があれば十分（Javaは
  ライブラリのバージョンを依存関係の宣言で管理するため、Pythonほど「環境の分離」を
  意識する場面は少ない） |
| プロジェクト実行 | `python main.py` | `mvn compile exec:java`（もしくはIDEから実行） |

Pythonの`pip`は「ライブラリをインストールするだけ」のツールですが、Mavenや
Gradleは「依存管理＋コンパイル＋テスト＋パッケージ化」までを1つの設定ファイルと
コマンドでまとめて行う点が異なります。これは、Javaがコンパイル言語であり、
「ビルド」という工程自体がPython（インタプリタ言語）よりも重要な意味を持つためです。

## 4. つまずきやすいポイント・よくある間違い

- **ディレクトリ構成を無視してファイルを置いてしまう**：`src/main/java`以外の場所に
  ソースコードを置くと、ビルドツールがファイルを見つけられずビルドに失敗します
- **バージョンの指定忘れ・衝突**：複数のライブラリが同じライブラリの異なるバージョンに
  依存していると、「依存関係の衝突」が起きることがあります（最初のうちは
  「そういう問題がある」と知っておくだけで十分です）
- **`scope`（依存関係の適用範囲）の理解不足**：例えば`test`スコープのライブラリ
  （JUnitなど）は本番のコードには含まれません。「テスト時だけ必要」「常に必要」を
  区別する概念があることを覚えておきましょう
- **手動コンパイルの癖が抜けない**：ビルドツールを導入したら、`javac`を手で打つのでは
  なく`mvn compile`や`mvn test`のようにツール経由で操作する習慣に切り替えましょう
